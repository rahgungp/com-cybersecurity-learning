MODULE 04 · MINGGU KE-04

Authentication & Access Control

OWASPIAM Output: Access-Control Analysis

🎯 Learning Objectives

Setelah menyelesaikan materi ini, mahasiswa mampu:

  • Menjelaskan perbedaan Authentication dan Authorization.
  • Menjelaskan konsep password security dan Multi-Factor Authentication (MFA).
  • Menjelaskan IAM, Role-Based Access Control (RBAC), dan Least Privilege.
  • Menganalisis mekanisme access control pada sebuah skenario sistem.

📖 THEORY

Authentication vs Authorization

Authentication adalah proses membuktikan identitas pengguna ('siapa kamu?') — misalnya melalui password atau MFA. Authorization adalah proses menentukan apa yang boleh dilakukan pengguna tersebut setelah identitasnya terverifikasi ('apa yang boleh kamu akses?'). Alur umum: User → Authentication → Authorization → Resource.

Password Security & MFA

Kata sandi yang kuat, unik per layanan, dan dikelola melalui password manager mengurangi risiko credential stuffing. Multi-Factor Authentication (MFA) menambahkan lapisan verifikasi kedua (misal kode OTP atau aplikasi authenticator) sehingga kompromi password saja tidak cukup untuk mendapatkan akses.

IAM, RBAC, dan Least Privilege

Identity and Access Management (IAM) adalah kerangka kerja untuk mengelola identitas digital dan hak aksesnya secara terpusat. Role-Based Access Control (RBAC) memberikan izin berdasarkan peran (role) pengguna, bukan per individu, sehingga lebih mudah dikelola dan diaudit. Prinsip Least Privilege menyatakan bahwa pengguna hanya diberi akses minimum yang dibutuhkan untuk menjalankan tugasnya.

Session Security

Setelah autentikasi berhasil, sistem membuat sesi (session) yang perlu dilindungi — misalnya melalui token dengan masa berlaku terbatas, invalidasi sesi setelah logout, dan proteksi terhadap pencurian sesi (session hijacking).

Example

Seorang staf keuangan login ke sistem ERP menggunakan password dan kode OTP (authentication). Setelah berhasil, sistem memeriksa role-nya sebagai 'Staff Finance' dan hanya mengizinkan akses ke modul penggajian, bukan modul HR (authorization berbasis RBAC).

Case Study

Sebuah organisasi memberikan akun admin database kepada seluruh anggota tim developer 'agar lebih mudah', tanpa menerapkan RBAC maupun least privilege. Ketika salah satu akun developer dikompromikan melalui phishing, penyerang langsung mendapatkan akses penuh ke seluruh database produksi — dampak yang sebenarnya bisa dibatasi jika akses diberikan sesuai kebutuhan peran masing-masing.

Key Takeaways

  • Authentication membuktikan identitas; Authorization menentukan hak akses.
  • MFA secara signifikan mengurangi risiko kompromi akun akibat password bocor.
  • RBAC menyederhanakan pengelolaan akses berdasarkan peran, bukan individu.
  • Least Privilege membatasi dampak jika satu akun dikompromikan.
