MODULE 05 · MINGGU KE-05

Cryptography & Data Protection

OpenSSLTLSAES Output: Encryption / Hashing Demonstration

🎯 Learning Objectives

Setelah menyelesaikan materi ini, mahasiswa mampu:

  • Menjelaskan perbedaan Encryption, Hashing, dan Digital Signature.
  • Menjelaskan konsep PKI, TLS, dan certificate.
  • Membedakan perlindungan data at rest dan data in transit.
  • Melakukan demonstrasi hashing dan enkripsi dasar secara aman.

📖 THEORY

Encryption vs Hashing vs Digital Signature

Encryption mengubah plaintext menjadi ciphertext menggunakan kunci, dan dapat dibalik (didekripsi) menggunakan kunci yang sesuai — digunakan untuk kerahasiaan data. Hashing mengubah input menjadi nilai hash berukuran tetap secara satu arah (tidak dapat dibalik) — digunakan untuk verifikasi integritas, misalnya menyimpan password secara aman. Digital Signature menggabungkan hashing dan kriptografi kunci privat untuk membuktikan keaslian dan integritas pesan.

PKI, TLS, dan Certificate

Public Key Infrastructure (PKI) adalah sistem yang mengelola pasangan kunci publik-privat serta sertifikat digital yang menghubungkan identitas dengan kunci publik tersebut. TLS (Transport Layer Security) menggunakan PKI untuk mengamankan komunikasi di internet, misalnya HTTPS pada browser. Certificate diterbitkan oleh Certificate Authority (CA) tepercaya untuk membuktikan bahwa sebuah kunci publik memang milik entitas yang mengklaimnya.

Data at Rest vs Data in Transit

Data at rest adalah data yang tersimpan pada media seperti disk atau database, dilindungi misalnya dengan enkripsi disk (AES). Data in transit adalah data yang sedang berpindah melalui jaringan, dilindungi misalnya dengan TLS. Keduanya memerlukan pendekatan perlindungan berbeda meskipun tujuannya sama: menjaga kerahasiaan dan integritas.

Example

Saat mahasiswa login ke portal akademik melalui HTTPS, data password dikirim melalui koneksi yang dilindungi TLS (data in transit). Di sisi server, password tersebut tidak disimpan apa adanya, melainkan disimpan dalam bentuk hash (misalnya menggunakan algoritma bcrypt) sehingga meskipun database bocor, password asli tidak langsung terbongkar.

Case Study

Sebuah aplikasi menyimpan password pengguna dalam bentuk plaintext di database (tanpa hashing). Ketika database bocor akibat vulnerability lain, seluruh password pengguna langsung terekspos tanpa perlu proses tambahan oleh penyerang — berbeda jika password disimpan dalam bentuk hash yang kuat, di mana penyerang masih harus melakukan upaya tambahan (misalnya cracking) untuk mendapatkan password asli.

Key Takeaways

  • Encryption bersifat dua arah (reversible); hashing bersifat satu arah (irreversible).
  • Digital signature membuktikan keaslian dan integritas, bukan kerahasiaan.
  • TLS + PKI melindungi data in transit; enkripsi disk melindungi data at rest.
  • Password sebaiknya disimpan dalam bentuk hash yang kuat, bukan plaintext maupun terenkripsi biasa.
