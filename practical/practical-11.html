PRACTICAL LAB · MINGGU 11

Vulnerability Management

🧪 Vulnerability Assessment

⏱ 45–60 menitReferensi Output: Vulnerability Assessment

Objective

Mahasiswa mampu melakukan vulnerability assessment sederhana pada mesin virtual yang sengaja dibuat rentan di lingkungan lokal, dan menyusun laporan temuan.

Scenario

Mahasiswa menjalankan intentionally vulnerable VM (misal Metasploitable) pada lingkungan virtualisasi lokal milik sendiri (authorized target only).

Tools

  • Nmap
  • OpenVAS / Greenbone (opsional)
  • NVD (untuk mencari detail CVE)

Environment

WAJIB local lab dengan target yang sah milik sendiri (intentionally vulnerable VM). Dilarang keras memindai (scan) target di luar lingkungan lokal tanpa izin eksplisit.

Instructions

  1. Jalankan Nmap terhadap target VM lokal untuk mengidentifikasi port dan layanan yang terbuka.
  2. Identifikasi minimal satu layanan dengan versi yang berpotensi memiliki kerentanan yang diketahui.
  3. Cari CVE terkait layanan tersebut pada NVD.
  4. Catat CVSS score dan deskripsi singkat kerentanan tersebut.
  5. Tentukan apakah CVE tersebut juga tercantum di CISA KEV.
  6. Susun rekomendasi remediasi.

Expected Output

Tabel vulnerability assessment: Vulnerability ID (CVE), Severity (CVSS), Description, Affected Asset, Risk, Recommendation.

Analysis

  • Mengapa sebuah CVE dengan skor CVSS sedang bisa jadi lebih mendesak untuk ditangani dibanding CVE dengan skor lebih tinggi?
  • Apa perbedaan antara menemukan kerentanan (assessment) dan benar-benar memperbaikinya (remediation)?

Questions

  1. Apa fungsi CISA KEV dalam membantu prioritisasi remediasi?
  2. Mengapa scanning hanya boleh dilakukan pada target yang sah (authorized)?

Assignment

Susun Vulnerability Assessment Report lengkap sesuai format tabel yang ditentukan berdasarkan target VM lokal.
