PRACTICAL LAB · MINGGU 12

Security Monitoring & Incident Response

🧪 Security Log Analysis

⏱ 45–60 menitReferensi Output: Log Analysis

Objective

Mahasiswa mampu menganalisis sample log keamanan dan menentukan severity serta tindakan yang direkomendasikan mengikuti alur SOC workflow.

Scenario

Mahasiswa diberikan kumpulan sample log autentikasi seperti berikut:

2026-09-14 09:20:11 FAILED LOGIN user=admin source=192.168.1.50
2026-09-14 09:20:13 FAILED LOGIN user=admin source=192.168.1.50
2026-09-14 09:20:15 FAILED LOGIN user=admin source=192.168.1.50
2026-09-14 09:21:02 SUCCESSFUL LOGIN user=admin source=192.168.1.50
2026-09-14 14:05:40 SUCCESSFUL LOGIN user=budi.santoso source=10.0.0.22

Tools

  • Worksheet log analysis (disediakan)

Environment

Sample log simulasi — bukan log sistem produksi nyata.

Instructions

  1. Untuk setiap baris log, catat event, source, target (user), dan timestamp.
  2. Tentukan severity tiap event (Low/Medium/High).
  3. Identifikasi pola yang berpotensi menjadi threat (misal percobaan login berulang diikuti keberhasilan).
  4. Tentukan tahap SOC workflow yang sesuai untuk pola tersebut (Triage/Investigation/Containment/dst).
  5. Usulkan recommended action untuk pola yang mencurigakan.

Expected Output

Tabel log analysis: Event, Source, Target, Timestamp, Severity, Possible Threat, Recommended Action.

Analysis

  • Mengapa 3 failed login diikuti 1 successful login lebih mencurigakan dibanding 1 failed login saja?
  • Tahap SOC workflow mana yang paling penting dilakukan sebelum mengambil tindakan containment?

Questions

  1. Apa perbedaan antara event dan alert dalam konteks monitoring?
  2. Mengapa dokumentasi (lessons learned) penting meskipun insiden sudah selesai ditangani?

Assignment

Susun Log Analysis Report berdasarkan sample log di atas, lengkap dengan severity dan recommended action.
